# TailWatcher

Headless StartOS 0.4 service: watches tail numbers and airline flight numbers on free ADS-B feeds and pushes NTFY alerts on takeoff (optionally landing), with links to ADS-B Exchange. Config is a list of **watchers** (name, NTFY topic, aircraft list, landing toggle, priority); each tail/callsign is polled once and fanned out to every watcher following it. Aircraft entries are `{tail, label, kind: 'tail'|'flight', expires: unix|null}` (`tail` holds the flight number for flights).

## Layout

- `app/tailwatcher.py` — the watcher (Python stdlib only). Reads `/data/config.json`, keeps per-aircraft state in `/data/state.json`, serves `/health` on :8080, publishes JSON to `$NTFY_URL`.
- `app/flights.py` — IATA→ICAO airline map, `parse_flight()` (the tail-vs-flight rule), callsign matching on the trimmed `flight` field.
- `app/commands.py` — text commands: one ntfy JSON stream per watcher topic (`TopicListener`), `parse()` (incl. expiry phrases), `apply_command()` and `remove_expired()`, which edit `config.json` under `CONFIG_LOCK`. The entry shape must match `startos/fileModels/config.json.ts`. Messages tagged with `OWN_TAGS` (airplane, airplane_arriving, robot, test_tube) are TailWatcher's own and ignored, so keep every published message tagged.
- `app/lookup.py` — the `info N12345` command: FAA N-number page (parsed from HTML via `data-label` cells), hexdb.io, live feed (adsb.fi) and planespotters.net photo, fetched in parallel; each source optional. Replies show owner city/state only, never street. planespotters requires a contact URL in the User-Agent (USER_AGENT has one) and photo credit in the message. The FAA site rejects non-browser user agents, hence FAA_UA.
- `app/trips.py` — "where's my plane?" trips: `parse_inbound()` (manual "inbound UA1234 N38473 dep 4:30pm"), AeroDataBox via RapidAPI (`resolve()`: /flights/number/{flight}/{date} for your leg and assigned reg, then /flights/reg/{reg}/{date} for the inbound leg; headers X-RapidAPI-Key/X-RapidAPI-Host; free tier 1 req/s), `check_level()` (light 1-request checks weekly >14 days out, daily until 1 day out; full 2-request checks at 24h/6h/2h/45m), missing-flight detection with `find_replacement()` (airport departures board ±3h, same airline + destination; suggested via "change N X", never applied automatically), `scan()`/`apply_change()`/`select()`/`modify()` for numbered "trips"/"change"/"cancel", and `step()` which turns each cycle's ADS-B fix for the inbound plane into on-its-way / tight / late / running-later / landed alerts. Trips live in `/data/trips.json` (not config.json, so Configure can't wipe them) under `TRIPS_LOCK`; `track_trips()` in tailwatcher.py runs them after the normal poll. adsbdb.com gives a callsign's route, used to tell the leg into your airport from earlier legs.
- Round trips (0.16.0): each flight is still an ordinary trip, linked by `itinerary` id with `leg` "out"/"return" (`parse_itinerary()` splits on "return"; `return N …` → `on_return()`/`link_return()`). `ordered()` (not `sort_key`) numbers trips so a journey's legs stay adjacent; `modify_legs()` gives `cancel`/`share` both legs unless the text says "only"; `change` stays per leg via `modify()`. The return's `dep_airport` defaults to the outbound's `arr_airport` (also filled in by `track_trips()` once AeroDataBox knows it). Typed times are in the departure airport's zone (`trips.airport_zone()`, from the `tz` column of airports.csv, which `trim_airports.py` fills from mwgg/Airports at build time: ICAO, then IATA, else nearest within 150 nm), falling back to `timeZone`; display stays in `timeZone`. `snapshot()` sends `dep_tz` so the edit form prefills the time in that zone.
- `app/web.py` + `app/web/index.html` — the read-only Web UI on port 8080 (StartOS interface "ui"): no login by default (the user's call: it's a household admin panel showing everyone's watchers, reachable only on LAN/VPN on StartOS 0.4; no per-user accounts or privacy silos). "Require Web UI Password" (`webPassword` in config) turns on HTTP Basic auth with the password in `/data/webui.json` (written by StartOS init; "Show/Reset Web UI Password" actions); `/health` always stays open for the ready check. `/api/state` is built by `snapshot()` in tailwatcher.py and must never include the NTFY token or AeroDataBox key. index.html is one self-contained file (no CDN, so it works over Tor); escape everything with `esc()` since history includes user-typed commands. Two themes, switched in the header and kept in localStorage per browser: Modern and Board (`.theme-board`, always dark): trips/aircraft use `renderTripsBoard`/`renderWatchersBoard` and split-flap `flaps(key, text, n)` tiles, which flip only the characters that changed since the last refresh (`PREV`), never on first render, and not with reduced motion. The user rejected mixing board and terminal looks in one theme; a separate Terminal theme is a possible later addition.
- Trip sharing: `trip["shared_with"]` lists other watchers' topics. `own_live()` follows your own flight's callsign only from 3h before to 20h after departure (the same flight number flies daily); `track_trips()` runs `observe()` on it (`trip["own"]`, `trip["own_sent"]`) and sends departed/landed via `build_message()` to the shared topics, plus `share_note_messages()` for AeroDataBox time changes/disappearances (never plane swaps). Sharing is set via `set_share()`/`on_share()` in tailwatcher.py (web form "Share with" checkboxes, or `share N name` / `unshare N name` texts) and announced once with `share_announcement()`.
- `app/edits.py` — Web UI edits for watchers and aircraft (`save_watcher`/`remove_watcher`/`save_aircraft`/`remove_aircraft`, raising `EditError` for messages shown in the form), under `CONFIG_LOCK`; renaming a watcher's topic moves its trips. Trip edits go through the same `on_inbound`/`on_change`/`on_cancel` closures as the text commands via `trip_text()` in tailwatcher.py's `handle_post()`. POSTs need `Content-Type: application/json`, `X-TailWatcher: 1` and a same-origin Origin (CSRF guard, since the UI may be public with no password). `snapshot()` and `handle_post()` read config.json fresh because `cfg` only refreshes at the top of a poll cycle (which can sit in a rate-limit backoff for minutes).
- ? Help in the Web UI renders `instructions.md` (copied into the image as /app/web/guide.md, served at /guide.md) with a small Markdown-subset renderer (`renderBlocks`/`parseGuide` in index.html: headings, paragraphs, lists with one nesting level, tables, quotes) plus search and `data-section` deep links. instructions.md is therefore both the StartOS Instructions tab and the in-app guide: keep it task-organized (## topics, ### troubleshooting questions) and stick to that Markdown subset. test_web checks every data-section link matches a heading.
- `app/invites.py` — invite links (`/join/<token>`, public: they skip the dashboard password and show one watcher's subscribe page). Tokens are random (`secrets.token_urlsafe(18)`), expire (1–30 days, default 7), can be revoked, live in `/data/invites.json`, and carry `kind` ("watcher") so group trips can reuse them. The link base is TAILWATCHER_PUBLIC_URL (TailWatcher's own public HTTPS address, from main.ts) because SMS/iMessage/Signal only linkify https, not ntfy://. Everything on the join page is `html.escape`d.
- `app/history.py` — ring buffer of sent/received messages (`/data/history.json`), recorded in `send()` and `on_command()`.
- `app/test_*.py` — unit tests (`make test`); `app/testdata/faa_N17169.html` is a real FAA page for the parser test.
- `Dockerfile` — python:3.12-alpine; bakes a trimmed OurAirports CSV for "nearest airport".
- `startos/` — StartOS package (SDK 1.5.2, same as the homebrew-suite packages). `actions/configure.ts` is the settings form, written to `config.json` via `fileModels/config.json.ts`; `main.ts` resolves NTFY's bridge address; the watcher hot-reloads `config.json` by mtime (Configure and text commands both write it), so config changes don't restart the service.

## Build

- `make x86` → `tailwatcher_x86_64.s9pk` (docker build of `start9/tailwatcher/main:0.16.2`, then `start-cli s9pk pack`). No buildx on this machine, so aarch64 isn't built.
- Packing needs a git commit (it records the hash) and the `assets/` dir.
- `make install` sideloads to the host in `~/.startos/config.yaml`.

## Gotchas

- `info` runs in the topic listener thread, outside CONFIG_LOCK; `apply_command` returns (None, False) for it. `on_info` lives inside `run()` in tailwatcher.py, so a missing module import only fails live; `test_lookup` checks the import.
- Notification server (0.12+): `ntfyServer` = public (ntfy.sh, default for new installs; no NTFY package, unguessable `tw-<name>-<20 random>` topics from `edits.new_topic()` / `newTopic()` in startos/utils.ts are the only lock), local (this Start9's NTFY via NTFY_URL; pre-0.12 installs migrated here) or custom (`ntfyCustomUrl`). `resolve_ntfy()` never sends the token to ntfy.sh. The NTFY dependency is optional and only declared when local. main.ts passes NTFY_PHONE_URL (NTFY's public or .local HTTPS address) for the dashboard's "Connect phone" `ntfy://host/topic` links. The user's goal: setup should need TailWatcher only, like Canary.
- Web UI ⚙ Settings (`openSettings()` in index.html) edits the same config.json as Configure via `edits.save_settings()` (only given keys change; blank secret fields mean unchanged). "Set up NTFY for me" (`ntfy_admin.setup()`, POST /api/ntfy-setup) uses NTFY's admin API with the typed admin password, never stored: creates/resets user `tailwatcher` (409 → PUT), grants it rw on `tw-*`, phones `open` = anonymous user `*` rw on `tw-*` (NTFY's API name for anonymous) or `login` = revoke that and `create_login()` per watcher, then mints a token as `tailwatcher`. `ntfyPhoneMode` records the choice.
- NTFY on StartOS is deny-all. TailWatcher uses a token for a **regular** NTFY user (`tailwatcher`) with Read-Write on `tailwatcher*`, minted in the NTFY web UI (Account → Access tokens; same as POST /v1/account/token). NTFY's Provision Publisher makes a `pkg_` account that is write-only, and Grant User Topic Access hides `pkg_` users, so a publisher token can send alerts but never read text commands. A 403 on the command stream shows in health and retries every 60s.
- AeroDataBox: the API.market listing is a 7-day trial; the RapidAPI Basic plan is the free one (400 requests/month). Its webhooks need TailWatcher reachable from the internet, so trips poll at checkpoints instead. Sample responses in test_trips.py follow the OpenAPI spec (doc.aerodatabox.com/docs/openapi-rapidapi-v1.json) and haven't been checked against a live key yet.
- Airport codes: 3 letters resolve as IATA first (some small airport's ident is often the same 3 letters, e.g. "LAS"); airports.csv carries an `iata` column for this.
- Arrival estimates assume 420 kt while a plane is below 15,000 ft and 150+ nm out (climb-out groundspeed is far too pessimistic); only later-moving estimates are announced.
- Publish failures: transient ones (network, 429, 5xx) go to a per-delivery retry queue in `state.json` `_retry` (30 min), so other watchers never get duplicates; 4xx refusals aren't retried and show in health.
- Config format changed in 0.2.0 (top-level `aircraft`/`ntfyTopic` → `watchers`). `versions/current.ts` migrates on update, and `load_config` in Python also accepts the old format.
- The Configure form nests a list (aircraft) inside a list item (watcher). The SDK types allow it; check it renders well in the StartOS UI before relying on deeper nesting.
- Dependency title/icon only show if `manifest.dependencies.ntfy.s9pk` points at a real NTFY s9pk; a `metadata` block is ignored by start-cli.
- airplanes.live now requires approval (403); data sources are adsb.fi (default) and adsb.lol. adsb.lol's headers say 4/s, 60/min and **500/day**, which one-request-per-aircraft polling blew through, so each cycle now does one batched poll (`fetch_many`: comma-separated keys, 25 per request, tails and callsigns separately) covering watched aircraft plus `trip_poll_keys()`; `poll_all` falls back to the other feed on errors/429. Never reintroduce per-aircraft requests in the loop.
- Detection: ground→air = "departed"; first seen airborne after 20+ min unseen = "is airborne" (small fields lack ground coverage).
- A stored "ground" status never changes once a parked plane stops transmitting, so `snapshot()` sends `live` (seen within GAP_SECONDS): the dashboard shows "Parked · seen X ago" (Board: PARKED) when not live, and `mapLink(a)` only links live planes. Next to it, `where` (from `Airports.place()` on the last fix) gives a plain-text location: "at KFDK – …" on the ground (within 3 nm), else "near City, ST" / "N nm NE of City, ST" from medium/large airports' `city`/`region` columns (added to airports.csv by trim_airports.py; US/CA/AU use the state, elsewhere the country code), else coordinates; non-live planes show it as "last seen …".
- Flights are polled by callsign (`/v2/callsign/{CS}` on both adsb.lol and adsb.fi) and state is keyed by callsign, so "UA1234" and "UAL1234" are one entry. Tail-vs-flight rule lives in `flights.parse_flight` (dash or N+digit → tail; 3 letters+digits or a known IATA code+1–4 digits → flight; else tail). New Python modules must be added to the Dockerfile `COPY` line.
- Expiry: the watcher calls `remove_expired()` at the top of each cycle and posts "⌛ Stopped watching X (expired)"; `load_config` also skips expired entries. "until fri" = 3am the next day in `timeZone` (Configure, default America/New_York); the container is UTC, so never use the container date. The Configure form shows `expiresDays`; saving it unchanged keeps the stored `expires`.

# TailWatcher

Headless StartOS 0.4 service: watches tail numbers and airline flight numbers on free ADS-B feeds and pushes NTFY alerts on takeoff (optionally landing), with links to ADS-B Exchange. Config is a list of **watchers** (name, NTFY topic, aircraft list, landing toggle, priority); each tail/callsign is polled once and fanned out to every watcher following it. Aircraft entries are `{tail, label, kind: 'tail'|'flight', expires: unix|null}` (`tail` holds the flight number for flights).

## Layout

- `app/tailwatcher.py` — the watcher (Python stdlib only). Reads `/data/config.json`, keeps per-aircraft state in `/data/state.json`, serves `/health` on :8080, publishes JSON to `$NTFY_URL`.
- `app/flights.py` — IATA→ICAO airline map, `parse_flight()` (the tail-vs-flight rule), callsign matching on the trimmed `flight` field.
- `app/commands.py` — text commands: one ntfy JSON stream per watcher topic (`TopicListener`), `parse()` (incl. expiry phrases), `apply_command()` and `remove_expired()`, which edit `config.json` under `CONFIG_LOCK`. The entry shape must match `startos/fileModels/config.json.ts`. `HELP` (the "help" reply) is grouped trips first (your trips, change, share), then watching planes; keep instructions.md's Text commands table in the same order. Messages tagged with `OWN_TAGS` (airplane, airplane_arriving, robot, test_tube) are TailWatcher's own and ignored, so keep every published message tagged.
- `app/lookup.py` — the `info N12345` command: FAA N-number page (parsed from HTML via `data-label` cells), hexdb.io, live feed (adsb.fi) and planespotters.net photo, fetched in parallel; each source optional. Replies show owner city/state only, never street. planespotters requires a contact URL in the User-Agent (USER_AGENT has one) and photo credit in the message. The FAA site rejects non-browser user agents, hence FAA_UA.
- `app/trips.py` — "where's my plane?" trips: `parse_inbound()` (manual "inbound UA1234 N38473 dep 4:30pm"), AeroDataBox via RapidAPI (`resolve()`: /flights/number/{flight}/{date} for your leg and assigned reg, then /flights/reg/{reg}/{date} for the inbound leg; headers X-RapidAPI-Key/X-RapidAPI-Host; free tier 1 req/s), `check_level()` (light 1-request checks weekly >3 days out (`DAILY_DAYS`, 0.24.0; was 14), daily until 1 day out; full 2-request checks at 24h/6h/2h/45m; a failed check sets `trip["adb_wait"]` from `AdbError.wait` instead of retrying every cycle), missing-flight detection with `find_replacement()` (airport departures board ±3h, same airline + destination; suggested via "change N X", never applied automatically), `scan()`/`apply_change()`/`select()`/`modify()` for numbered "trips"/"change"/"cancel", and `step()` which turns each cycle's ADS-B fix for the inbound plane into on-its-way / tight / late / running-later / landed alerts. Trips live in `/data/trips.json` (not config.json, so Configure can't wipe them) under `TRIPS_LOCK`; `track_trips()` in tailwatcher.py runs them after the normal poll. adsbdb.com gives a callsign's route, used to tell the leg into your airport from earlier legs.
- Round trips (0.16.0): each flight is still an ordinary trip, linked by `itinerary` id with `leg` "out"/"return" (`parse_itinerary()` splits on "return"; `return N …` → `on_return()`/`link_return()`). `ordered()` (not `sort_key`) numbers trips so a journey's legs stay adjacent; `modify_legs()` gives `cancel`/`share` both legs unless the text says "only"; `change` stays per leg via `modify()`. The return's `dep_airport` defaults to the outbound's `arr_airport` (also filled in by `track_trips()` once AeroDataBox knows it). Typed times are in the departure airport's zone (`trips.airport_zone()`, from the `tz` column of airports.csv, which `trim_airports.py` fills from mwgg/Airports at build time: ICAO, then IATA, else nearest within 150 nm), falling back to `timeZone`; display stays in `timeZone`. `snapshot()` sends `dep_tz` so the edit form prefills the time in that zone.
- Connections and through flights (0.17.0): `seq` orders a journey's flights (old round trips have none; `leg_order()` falls back to out=0/return=1); two adjacent flights with the same `leg` are a connection (`connects_from()`/`connects_to()`, `prev_leg()`). `parse_itinerary()` returns a list of legs, splitting on `return` then on `then`/`connecting`/`connect` (`parse_connection()`: same day as the leg before, next day if the time is earlier); `connect N …` → `on_connect()`/`attach()` (inserts after N, renumbers `seq`). Connection alerts follow your own flight: `own_live(trip, now, connecting=True)` polls its callsign even when unshared; `own_event()` turns observe() events into departed/landed once (shared alerts and `connection_step()` both use it); `connection_notes()` warns before the day from AeroDataBox `arr_time`. Add trip form (0.20.3): the return sits in a collapsed `group` (`<details>`) and connections are a `legs` field with "+ Add connection" blocks named by `trips.form_prefix()` (`conn_`, `conn2_`, … / `ret_conn_`, `ret_conn2_`, …; `MAX_LEGS` 8 each way, `MAX_CONNECTIONS` in index.html must stay `MAX_LEGS - 1`); `handle_post()` chains them with `then` on add, and on Edit adds each with `on_connect()` after the one before. Through flights: `resolve()` builds the flight number's chained legs (`through_route()`), `ride()` cuts it at `get_off` ("to DEN"), storing `route`, `stops`, `arr_airport`, `arr_time`; `pick_inbound()` no longer skips your own flight number (boarding at the stop, that's the inbound leg), `step()` skips the adsbdb route check for it, and `own_event()` ignores a takeoff before your stop (`boards_midway()`) and a landing within STOP_NM of a stop.
- `app/itinerary.py` (0.18.0) — Import: `preview()` reads pasted text, a saved .eml, an .ics or .html into flights (schema.org FlightReservation JSON-LD first, then calendar events, then a text scan: `find_flights()` for `UA 1234` / `United 1234`, nearest `find_dates()`/`find_times()`/airport codes, layout = details after the number unless two codes precede it), groups them with `journeys()` (≤1 day apart from where the last landed = connection, next group = return) and returns Add trip form values via `to_form()`. Read only and offline: POST /api/import (3 MB, `web.MAX_IMPORT`) just pre-fills `tripForm(null, pre, intro)` in index.html, which the person checks and saves as usual. PDFs/images/Word are refused with the copy-the-text message; keep `SUPPORTED`/`NOT_SUPPORTED`, the Import dialog and instructions.md's Importing a trip saying the same thing. Planned next (Sam, 2026-10-20): optional AI Smart fill with the user's own provider key (presets + OpenAI-compatible custom, Anthropic native), PDFs only to providers that accept them, result still only pre-fills the form.
- `app/web.py` + `app/web/index.html` — the Web UI on port 8080 (StartOS interface "ui"). Sign-in mode `webAuth` in config (0.22.0): `off` (no login; StartOS default), `password` (one shared password from `/data/webui.json`, written by StartOS init; "Show/Reset Web UI Password" actions; Docker default) or `accounts` (Family accounts, below). Legacy `webPassword` maps to off/password; a fresh install (no webAuth, webPassword or watchers) gets `me.setup` and a first-setup dialog to pick one. Login is a form posting to /login that sets an HttpOnly SameSite=Lax `tw_session` cookie (30 days, sliding; Secure behind https); Basic auth still works in password mode; the form posts Origin "null" (no-referrer), which is allowed. 5 failures/15 min per address or username → 30 s waits. `/health`, `/join/`, `/login` and the forgot-password pages (`/login?forgot`, POST `/forgot`, `/reset`) always stay open. The plain-HTML pages (login, forgot, reset, sign-up) are built with `web.form_page()`. `/api/state` is built by `snapshot()` in tailwatcher.py and must never include the NTFY token or AeroDataBox key. index.html is one self-contained file (no CDN, so it works over Tor); escape everything with `esc()` since history includes user-typed commands. Two themes, switched in the header and kept in localStorage per browser: Modern and Board (`.theme-board`, always dark): trips/aircraft use `renderTripsBoard`/`renderWatchersBoard` and split-flap `flaps(key, text, n)` tiles, which flip only the characters that changed since the last refresh (`PREV`), never on first render, and not with reduced motion. The user rejected mixing board and terminal looks in one theme; a separate Terminal theme is a possible later addition. Activity (`renderFeed`) is a scroll box on wide screens; at ≤900 px it shows the newest `FEED_STEP` (8) entries with Show more (+20) / Show less (0.22.1).
- Trip sharing: `trip["shared_with"]` lists other watchers' topics. `own_live()` follows your own flight's callsign only from 3h before to 20h after departure (the same flight number flies daily); `track_trips()` runs `observe()` on it (`trip["own"]`, `trip["own_sent"]`) and sends departed/landed via `build_message()` to the shared topics, plus `share_note_messages()` for AeroDataBox time changes/disappearances (never plane swaps). Sharing is set via `set_share()`/`on_share()` in tailwatcher.py (web form "Share with" checkboxes, or `share N name` / `unshare N name` texts) and announced once with `share_announcement()`.
- `app/edits.py` — Web UI edits for watchers and aircraft (`save_watcher`/`remove_watcher`/`save_aircraft`/`remove_aircraft`, raising `EditError` for messages shown in the form), under `CONFIG_LOCK`; renaming a watcher's topic moves its trips. Trip edits go through the same `on_inbound`/`on_change`/`on_cancel` closures as the text commands via `trip_text()` in tailwatcher.py's `handle_post()`. POSTs need `Content-Type: application/json`, `X-TailWatcher: 1` and a same-origin Origin (CSRF guard, since the UI may be public with no password). `snapshot()` and `handle_post()` read config.json fresh because `cfg` only refreshes at the top of a poll cycle (which can sit in a rate-limit backoff for minutes).

## Gotchas

- `info` runs in the topic listener thread, outside CONFIG_LOCK; `apply_command` returns (None, False) for it. `on_info` lives inside `run()` in tailwatcher.py, so a missing module import only fails live; `test_lookup` checks the import.
- Notification server (0.12+): `ntfyServer` = public (ntfy.sh, default for new installs; no NTFY package, unguessable `tw-<name>-<20 random>` topics from `edits.new_topic()` / `newTopic()` in startos/utils.ts are the only lock), local (this Start9's NTFY via NTFY_URL; pre-0.12 installs migrated here) or custom (`ntfyCustomUrl`). `resolve_ntfy()` never sends the token to ntfy.sh. The NTFY dependency is optional and only declared when local. main.ts passes NTFY_PHONE_URL (NTFY's public or .local HTTPS address) for the dashboard's "Connect phone" `ntfy://host/topic` links. The user's goal: setup should need TailWatcher only, like Canary.
- Web UI ⚙ Settings (`openSettings()` in index.html) edits the same config.json as Configure via `edits.save_settings()` (only given keys change; blank secret fields mean unchanged). "Set up NTFY for me" (`ntfy_admin.setup()`, POST /api/ntfy-setup) uses NTFY's admin API with the typed admin password, never stored: creates/resets user `tailwatcher` (409 → PUT), grants it rw on `tw-*`, phones `open` = anonymous user `*` rw on `tw-*` (NTFY's API name for anonymous) or `login` = revoke that and `create_login()` per watcher, then mints a token as `tailwatcher`. `ntfyPhoneMode` records the choice.
- NTFY on StartOS is deny-all. TailWatcher uses a token for a **regular** NTFY user (`tailwatcher`) with Read-Write on `tailwatcher*`, minted in the NTFY web UI (Account → Access tokens; same as POST /v1/account/token). NTFY's Provision Publisher makes a `pkg_` account that is write-only, and Grant User Topic Access hides `pkg_` users, so a publisher token can send alerts but never read text commands. A 403 on the command stream shows in health and retries every 60s. Topics made since 0.12 are `tw-…`, older ones `tailwatcher_…`, so hand-made tokens with only `tailwatcher*` 403 on new watchers (0.19.1): permission hints come from `commands.access_hint(topic)` (names the matching pattern and "Set up NTFY for me"), and `ntfy_admin.setup()` grants TailWatcher's user both `tw-*` and `tailwatcher*` (anonymous only ever `tw-*`).
- Phone certificates (0.20.4): a Start9 signs .local/LAN/IP addresses (StartTunnel's public IP included) with its own root CA, so a phone without it installed gets "Trust anchor for certification path not found" in the ntfy app with local/custom NTFY. StartTunnel forwards but doesn't change the cert, and Let's Encrypt won't sign IPs. Recommended fix for people outside the household: a public domain with Let's Encrypt on NTFY's interface through the StartTunnel gateway (docs.start9.com/start-os/0.4.0.x/public-access.html); own phones can install the root CA (…/trust-ca.html). instructions.md covers it (Connecting a phone + troubleshooting heading linked from Connect phone); the join page shows a hint when `server_mode` isn't public. `ntfyPhoneUrl`/`ownPublicUrl` in startos/utils.ts prefer a public domain (`kind: 'domain'`) over a public IP, which used to win depending on order.
- Subscription names (0.20.5): ntfy:// links carry `?display=TailWatcher · <watcher>` (`invites.display_name()`/`links()`, `connectInfo()` in index.html; keep them alike). Only the ntfy Android app reads `display`, and only when it creates the subscription; the iOS app has no display names or ntfy:// handling, and the web app only renames by hand. The server has no per-topic name setting, so this is as far as TailWatcher can go; Help's "The ntfy app shows a long random topic name" covers renaming by hand.
- AeroDataBox: the API.market listing is a 7-day trial; the RapidAPI Basic plan is the free one (400 requests/month). Its webhooks need TailWatcher reachable from the internet, so trips poll at checkpoints instead. Sample responses in test_trips.py follow the OpenAPI spec (doc.aerodatabox.com/docs/openapi-rapidapi-v1.json) and haven't been checked against a live key yet.
- Airport codes: 3 letters resolve as IATA first (some small airport's ident is often the same 3 letters, e.g. "LAS"); airports.csv carries an `iata` column for this.
- Arrival estimates assume 420 kt while a plane is below 15,000 ft and 150+ nm out (climb-out groundspeed is far too pessimistic); only later-moving estimates are announced.
- Publish failures: transient ones (network, 429, 5xx) go to a per-delivery retry queue in `state.json` `_retry` (30 min), so other watchers never get duplicates; 4xx refusals aren't retried and show in health.
- Config format changed in 0.2.0 (top-level `aircraft`/`ntfyTopic` → `watchers`). `versions/current.ts` migrates on update, and `load_config` in Python also accepts the old format.
- The Configure form nests a list (aircraft) inside a list item (watcher). The SDK types allow it; check it renders well in the StartOS UI before relying on deeper nesting.
- Dependency title/icon only show if `manifest.dependencies.ntfy.s9pk` points at a real NTFY s9pk; a `metadata` block is ignored by start-cli.
- airplanes.live now requires approval (403); data sources are adsb.fi (default) and adsb.lol. adsb.lol's headers say 4/s, 60/min and **500/day**, which one-request-per-aircraft polling blew through, so each cycle now does one batched poll (`fetch_many`: comma-separated keys, 25 per request, tails and callsigns separately) covering watched aircraft plus `trip_poll_keys()`; `poll_all` falls back to the other feed on errors/429. Never reintroduce per-aircraft requests in the loop.
- Detection: ground→air = "departed"; first seen airborne after 20+ min unseen = "is airborne" (small fields lack ground coverage).
- A stored "ground" status never changes once a parked plane stops transmitting, so `snapshot()` sends `live` (seen within GAP_SECONDS): the dashboard shows "Parked · seen X ago" (Board: PARKED) when not live, and `mapLink(a)` only links live planes. Next to it, `where` (from `Airports.place()` on the last fix) gives a plain-text location: "at KFDK – …" on the ground (within 3 nm), else "near City, ST" / "N nm NE of City, ST" from medium/large airports' `city`/`region` columns (added to airports.csv by trim_airports.py; US/CA/AU use the state, elsewhere the country code), else coordinates; non-live planes show it as "last seen …".
- Flights are polled by callsign (`/v2/callsign/{CS}` on both adsb.lol and adsb.fi) and state is keyed by callsign, so "UA1234" and "UAL1234" are one entry. Tail-vs-flight rule lives in `flights.parse_flight` (dash or N+digit → tail; 3 letters+digits or a known IATA code+1–4 digits → flight; else tail). New Python modules must be added to the Dockerfile `COPY` line.
- Expiry: the watcher calls `remove_expired()` at the top of each cycle and posts "⌛ Stopped watching X (expired)"; `load_config` also skips expired entries. "until fri" = 3am the next day in `timeZone` (Configure, default America/New_York); the container is UTC, so never use the container date. The Configure form shows `expiresDays`; saving it unchanged keeps the stored `expires`.
